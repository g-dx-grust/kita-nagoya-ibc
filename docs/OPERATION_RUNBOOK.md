# 操作ランブック — 7段階フローを頭から最後まで流す

このドキュメントは、ユーザーが定義した業務フロー（①過去実績→月間予測 → ②シフト→月間スケジュール → ③当日3部屋割り当て・印刷 → ④日報→実在庫 → ⑤予実差→月間反映 → ⑥原料不足アラート・発注期限 → ⑦発注書）を、実際の画面で**一連の作業として**流すための手順書です。各ステップに「画面」「操作」「期待結果」を記載します。

機能の自動回帰確認は `app/test/integration/e2e_full_flow.test.ts`（7段階を順に駆動する統合テスト）でも担保されています。

---

## 0. 準備（初回のみ）

```bash
cd app
npm install
npx prisma generate
npx prisma db push          # スキーマをdev.dbへ反映
npm run rebuild:products:classification          # 商品分類表のドライラン
npm run import:products      # 商品分類表をDBへ反映（旧商品は無効化）
npm run link:products:classification             # 紐づけのドライラン
npm run link:products:classification -- --apply  # 能力/手間賃/月次実績/包装BOMを反映
npm run db:seed             # デモ用データ投入（下記）
npm run dev                 # http://localhost:3000
```

`npm run import:products` は `docs/商品分類表 共有.xlsx` を正として商品マスターを作り直します。既存商品は削除せず無効化するため、過去の予定・日報・在庫台帳は旧商品IDに残ります。分類表に商品コード列がないため、画面上の `KCL-...` は内部管理コードです。実DBで実行する前は `app/prisma/dev.db` をバックアップしてください。

`npm run link:products:classification -- --apply` は、整合性監査CSVの exact/strong_spec 一致だけを使って旧商品の生産能力・手間賃・月次実績を新商品へコピーし、分類表の袋/トレー・ダンボール・備品・シール列から包装BOMを作ります。曖昧な「専用袋」や原料欄は自動BOM化せず、`docs/product_linking_unresolved_2026-06-08.csv` に要確認として残します。

> ⚠️ 既に実マスタ（商品5件以上）を投入済みの場合、`npm run db:seed` は **月次実績のみ** を再投入し、既存データは保持します（安全）。下記デモ一式（少数サンプル）を一から作り直す `SEED_FORCE_SAMPLE_RESET=1 npm run db:seed` は **既存の商品・在庫・予定などを全削除** するため、本番/実データ環境では実行しないでください。実データ運用では「①予測の元になる月次実績」と「②対象月のシフト」が入っていれば、デモseed無しでそのまま下記フローを流せます。

`npm run db:seed` で投入されるデモデータ（少数サンプルを新規作成する全リセットモード時）:
- 作業場所 4（一般部屋／機械部屋／仕上げ部屋＝社内3部屋、外注先A）
- 商品 P001(在庫・YEAR_RATIO・ケース24袋)、P002(受注・NONE)。P001にBOM(原料X 0.05kg＋標準袋1枚/個)・能力(一般部屋100袋/人時)・手間賃(12円/袋)
- 原料X(RM001, リードタイム3日, 安全在庫5, 発注ロット10kg)、原料Y、標準袋(PK001, 2000枚/ケース, 安全在庫500, 発注ロット2000)
- 仕入先「デフォルト仕入先」
- 従業員 5、シフト：**2026-05-20** と **2026-06-01〜06-05**（当月分。今日時点で当月スケジュールを組める）
- 期首在庫：原料X 20kg／標準袋 5000枚／商品A 200袋
- 月次実績(ProductMonthlyActual) 18か月（2024-12〜2026-05）。これが①予測の元データ
- ※ すでに実マスタ（商品5件以上）が入っている場合、`db:seed` は月次実績のみ再投入します。上記デモ一式を再作成したい場合は `SEED_FORCE_SAMPLE_RESET=1 npm run db:seed`。

> 実運用では、デモシフトの代わりに**実シフトをCSV取込**（手順②）または `/shifts` のグリッドで入力し、商品/原料/資材/月次実績も `/masters` のCSV取込で投入します。

## ① 月間生産予測（過去実績→YoY）

- 画面: `/product-planning`（または `/production-plans/monthly`）
- 操作: 対象月（例 **2026-06**）を選ぶ。
- 期待結果: 商品ごとに「前々月前年比（主）／前月前年比（参考）」と予測生産数が出る。
  - 計算: 前年当月(2025-06) × 前々月前年比(今年前々月2026-04 ÷ 前年前々月2025-04)。前々月が無い場合のみ前月前年比にフォールバック。
  - `forecastMethod=NONE` の商品（P002）は自動予測対象外。特需イベントで「通常予測に含めない」分は履歴から控除される。

## ② シフト取込 → 月間生産スケジュール（仮）

- 画面: `/shifts` … 当月シフトを確認。CSVがあれば**「シフトCSV取込」**から取り込み可（前月15日に出るシフト表を想定）。
  - 取込は**既存従業員（正式名称）にのみ紐付け**、未知名はスキップして警告（社員マスタは壊さない）。
- 画面: `/production-plans/monthly`
- 操作: 期間（例 2026-06-01〜06-05）を指定して**「シフト連動で仮予定生成」**を押す。
- 期待結果: 予測数量とシフト能力から **draft の生産予定** が複数生成される（誰が・いつ・どの部屋・何個）。同画面に **「当月 予実・過不足」表**（目標／実績累計／未完了予定／残目標／過不足）も表示。

## ③ 当日：3部屋割り当て・作業表印刷

- 画面: `/production-plans/allocate`
- 操作: 日付（例 2026-06-01）を選び、自動割り当て→必要なら手修正→**保存**。
- 期待結果: 「部屋レーン×時間」「人×時間」の2ビューで、誰がどの部屋で何時から何を作り、**完了後どの部屋へ移動するか**が出る。
- 画面: `/prints/staff-assignments`・`/prints/production-schedule`
- 操作: 印刷（部屋ごとに改ページ）。作業表の「移動」列に **部屋A → 部屋B** の移動が表示される。

## ④ 日報入力 → 実在庫反映

- 画面: 生産予定の詳細 `/production-plans/[id]`（日報フォーム）または `/daily-reports`
- 操作: 実人数・実時間・**実数量**・**実原料/資材使用量**を入力 → 下書き保存 → **確定**。
- 期待結果:
  - 確定で **実績の在庫トランザクション（CONFIRMED）** が記録され、生産予定は `completed` に。
  - 予定在庫(PLANNED)は台帳に残るが**理論在庫は二重計上されない**（実績のみ）。`/inventory` で確認可。
  - **実績原価**（実数量×単価＋実使用原料/資材）が日報に保存される（予定原価とは別）。

## ⑤ 予実差 → 月間スケジュール反映

- 画面: `/production-plans/monthly`（再表示）
- 期待結果: 確定した実績が当月の **ProductMonthlyActual(sourceType=daily_report)** に自動集計され、「当月 予実・過不足」表に反映。提案数量は **残目標（予測 − 実績累計 − 未完了予定）** ベースに更新（完了分は二重に作り直さない）。最終的な追加/調整は **ユーザーが「仮予定生成」ボタンで判断**。

## ⑥ 原料不足アラート・発注期限

- 画面: `/inventory`（不足・マイナス・未確定入荷の判別）／`/purchases`／ホーム `/`
- 操作: `/purchases` で期間を指定し**「発注候補を生成」**。
- 期待結果:
  - **安全在庫を下回る前**に早期警告（below_safety）＋在庫ゼロ割れ（hard_shortage）の両方を候補化。
  - 各候補に **推奨発注日（不足日 − リードタイム）** と **緊急度**（描画時に再計算され陳腐化しない）。
  - 発注推奨数量は **発注ロット/最小発注数で切り上げ**（例 原料X→10kg単位）。
  - ホーム `/` に **「発注期限アラート」**（CRITICAL/期限超過）を表示。

## ⑦ 発注書作成

- 画面: `/purchases`
- 操作: 候補行の **「発注する」** を押す（candidate→ordered_unconfirmed）。→ **発注書ダウンロード（PDF / Excel）**。
- 期待結果:
  - **PDFは日本語表示**（仕入先名・品目名・項目名すべて）。**ケース数**併記。
  - Excelも同内容。仕入先名が実名で出る（`/masters/suppliers` で仕入先を管理し、原料/資材に紐付けてあれば「未設定」にならない）。
- 入荷時: 発注を「受領」にすると **確定入荷の在庫トランザクション** が立ち、在庫へ反映。

## 補足

- 仕入先マスタ: `/masters/suppliers`（追加/編集/無効化）。原料/資材マスタの編集フォームで仕入先を選択。CSV取込にも `supplier_name` 列あり。
- マスタCSVの雛形: `/api/export/master-template?type=...`（products/materials/packaging-materials/work-areas/shifts/capacities/product-monthly-actuals）。
- まだ未対応（将来/別対応）: ログイン/利用者ID（監査ログの「誰が」）、請求/売上CSVの請求先・摘要・二重出力防止、規格違い合算予測、営業予測専用入力。詳細は `docs/HANDOFF_2026-06-02.md`。
