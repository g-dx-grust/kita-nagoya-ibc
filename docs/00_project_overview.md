# 00. プロジェクト概要

## 目的

既存Excelで分散管理されている北名古屋拠点の製造業務を、Webシステム上で一気通貫に管理する。

現状は、受注・出荷・製品在庫、月間生産予定、原料/資材在庫、出勤表、作業部屋ごとの人員配分、日報、手間賃、実原価、売上伝票入力が別々のExcelや既存クラウドで動いている。これにより二重入力、在庫マイナスの見落とし、発注漏れ、製造時間見積もりの手計算、日報実績の反映遅れ、伝票入力ミスが起きやすい。

本システムでは、まず生産予定を手入力できる状態を作り、その予定を起点に下流の計算・在庫・発注・日報・請求出力を連動させる。

## 解決したい課題

- 生産予定を入れた時点で、必要な原料・資材・作業時間・手間賃・原価を見たい。
- 予定数量が多すぎて17時を超える、または在庫がマイナスになる場合に気づきたい。
- 原料/資材が不足する場合、発注候補と発注日/入荷予定を出したい。
- 発注済みでも未確定の入荷を、確定在庫と混同せずアラートしたい。
- 出勤表の人数や勤務時間を見ながら、作業場所へ人を割り振りたい。
- 日報の実績を入れたら、予定値から実績値へ置き換えて在庫・原価へ反映したい。
- 1時間1人あたりの生産量、手間賃、製造原価を自動集計したい。
- 売上伝票/請求書用データをCSV/Excelでまとめて出力し、二重入力を減らしたい。

## 初期スコープ

対象は北名古屋拠点を優先する。本社・外注先・製品在庫クラウドとの完全連携は将来フェーズとし、初期はマスター/CSV/手入力で成立する構成にする。

## 最重要方針

修正版文字起こしでは「ここはとりあえず手動であるとして」「ここから下を先に作ってくれると嬉しい」と整理されている。したがって、初期MVPは **製品在庫から自動で生産予定を組む部分ではなく、手動登録された生産予定から下流を自動化する部分** を優先する。

## 想定ユーザー

- 製造管理者: 月間/日別生産予定、作業場所割り振り、在庫不足、発注、日報確認
- 現場担当者: 当日作業予定、タブレット日報入力、実績数量/使用量入力
- 購買/発注担当者: 原料/資材の不足確認、発注登録、入荷確定
- 管理/経理担当者: 手間賃、原価、売上伝票/請求用データ出力
- システム管理者: 商品・原料・資材・作業場所・ユーザー・権限の管理

## 用語

| 用語 | 意味 |
|---|---|
| 生産予定 | いつ、何を、どれだけ、どの作業場所で、何人で作るかの予定 |
| 日報 | 実際の作業結果。実績数量、実績時間、実使用原料、作業人数など |
| 原料 | 製品の中身に使う材料。kg単位が中心 |
| 資材 | 袋、乾燥剤、段ボール等の包装・梱包資材 |
| 手間賃 | 製品/袋/ケースごとの作業単価または請求単価 |
| 作業場所/部屋 | 機械部屋、一般部屋、トラップ/トラック部屋等。正式名称はマスター管理 |
| 外注/AX | 外注先または外部作業場所。社内生産・請求対象とは扱いが異なる可能性あり |
| 未確定発注 | 発注は入れたが、入荷日・数量が確定していない状態 |
| 製品在庫クラウド | 製品在庫を管理している既存クラウド。初期は完全連携対象外 |
