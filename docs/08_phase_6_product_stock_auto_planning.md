# 08. Phase 6: 製品在庫連携・自動生産提案・AI/最適化

## 目的

将来的に、製品在庫クラウド、受注、出荷データを取り込み、在庫がマイナスになる商品や不足しそうな商品を自動抽出し、生産予定を提案する。

## 初期フェーズとの違い

Phase 1では生産予定を人が入力する。Phase 6では、製品在庫や需要予測をもとに、システムが生産候補数量を出す。

## 機能

- 製品在庫クラウドから在庫・受注・出荷データを取り込む
- マイナス在庫/不足見込みを検出する
- 受注生産と在庫生産を分ける
- 受注生産は必要数量ぴったりを基本にする
- 在庫生産は過去需要や月間消化量を見て、100ではなく200作る等の提案をする
- 月間生産予定は、前月確定前でも原料発注に使えるよう、前年対象月実績に今年前々月/前年前々月の前年比を掛けた予測を出す
- 作業場所、人員、原料/資材在庫を考慮して生産計画案を出す
- 17時超過、翌営業日持ち越し、残業候補を示す
- 人が承認した計画だけを確定予定にする

## AI/最適化の扱い

文字起こしでは「AIが90、90でポトポト」など将来像が出ている。ただし、初期実装ではルールベースで十分。AIは、過去需要からの提案や優先順位付けの補助として将来検討する。

## 受け入れ条件

- 製品在庫データをCSV/APIで取り込める。
- 不足商品一覧を表示できる。
- 商品ごとに受注生産/在庫生産ルールを持てる。
- 推奨生産数量を提示できる。
- 人が承認するまで確定予定にならない。
- 提案理由が表示される。
