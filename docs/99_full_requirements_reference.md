# 99. 統合要件定義リファレンス

## 1. 背景

北名古屋拠点では、受注・出荷・在庫・生産予定・原料/資材・出勤表・日報・伝票を複数のExcelや既存クラウドで管理している。現場では、在庫表を見てマイナスになりそうな商品を月間生産予定に入れ、作業場所や人数を見ながら予定を組み、原料/資材の不足を確認し、日報で実績を手入力し、別途売上伝票を入力している。

新システムでは、この流れを段階的に一元化する。特に初期MVPでは、製品在庫からの完全自動計画ではなく、人が入力した生産予定から下流の計算・在庫・発注・日報・請求出力を連動させる。

## 2. 初期MVPのゴール

- 生産予定を手動登録できる。
- 商品マスターから1時間1人あたり生産量を参照し、所要時間・終了時刻を算出できる。
- 9:00〜17:00等の時間枠から最大生産数量とあふれ数量を算出できる。
- 生産予定から原料・資材の予定使用量を算出できる。
- 原料/資材の不足、マイナス、未確定発注依存をアラートできる。
- 日報実績入力により、実使用量で在庫・原価を更新できる。
- 実績生産数量から請求/売上伝票用CSV/Excelを作成できる。

## 3. 業務要件

### 3.1 商品マスター

商品番号、正式商品名、別名、入り数、入数、受注生産/在庫生産区分、請求対象、標準作業場所、BOM、手間賃単価、生産能力を管理する。

文字起こしでは「パソコンの正式な登録名」「商品ナンバー」が重要とされているため、商品名の表記揺れを吸収する別名管理が必要である。

### 3.2 生産予定

生産予定には、生産日、商品、数量、作業場所、人数、開始時刻、終了希望時刻、仮/確定を登録する。登録時に、終了時刻、原料使用量、資材使用量、手間賃、原価、不足アラートを表示する。

### 3.3 計算モード

数量固定、時間枠固定、人数調整の3モードを実装する。

### 3.4 原料/資材在庫

予定使用量と実使用量を分ける。発注済みだが未確定の入荷は、確定在庫と別扱いにする。入荷確定後に確定入荷予定として反映し、入荷済みで実在庫へ加算する。

### 3.5 シフト/作業場所

出勤表から人数・勤務終了時刻を取り込み、作業場所へ割り振る。初期は人数割り振りでよく、後続で個人割り振りに対応する。作業が早く終わった場所から別の場所へ合流する候補を表示する。

### 3.6 日報

日報では実生産数量、実時間、実人数、実使用原料、実使用資材を入力する。日報確定時、予定値ではなく実績値を在庫・原価・請求へ反映する。

### 3.7 原価/手間賃

原料原価、資材原価、作業費、手間賃、1時間1人あたり実生産量を計算する。実原価と請求単価は別管理にする。

### 3.8 請求/伝票

日報確定済みの実生産数量から、商品別固定単価で請求/売上伝票用データを作成する。FXクラウド等の取り込み仕様が確認できたら、CSV/Excelの列を合わせる。

### 3.9 外注

AX等の外注先は、外部作業場所/部署として扱う。外注分は社内請求対象外になる可能性があるため、請求対象フラグを持つ。外注先在庫・戻り予定・原料移動は将来拡張とする。

### 3.10 製品在庫自動連携

将来フェーズで、製品在庫クラウドから在庫・受注・出荷を取り込み、マイナス予測から自動で生産候補を提案する。AI/最適化はこの段階で検討する。

## 4. 非機能要件

- PCでの計画・管理を優先し、日報はタブレット対応する。
- 重要操作は監査ログを残す。
- 在庫や日報確定の取り消しは権限を必要とする。
- CSV/Excel出力に対応する。
- 商品・原料・資材・作業場所のマスター変更履歴を残す。
- 将来の本社連携、外注連携、製品在庫連携に拡張できる構造にする。

## 5. 開発順序

1. 基盤とマスター
2. 手動生産予定と計算
3. 原料/資材在庫と発注
4. シフト/作業場所割り振り
5. 日報/実績/原価
6. 請求/伝票出力
7. 製品在庫連携と自動計画

## 6. 重要な実装注意点

- 「予定」と「実績」を混ぜない。
- 「未確定発注」と「確定入荷」を混ぜない。
- 「請求単価」と「実原価」を混ぜない。
- 商品名をキーにしない。
- 部屋名/外注先名をハードコードしない。
- 初期からAI自動計画を作り込まない。
