## 6. Phase 1 着手前に確定が必要な人系要件

`docs/18` §17 Phase 1 と Phase 5（タブレット日報運用は Phase 1 のマスタ設計に権限ロールが効くため早期確定が望ましい）から、**業務フロー視点で「誰が／いつ／どこまで」が分からないと進めない人系項目**を抽出。**ドキュメントに「未確定」「未確認」と書かれているもののみ**を抽出する。

1. **マスタ編集の権限ロール**（誰が商品/原料/BOM/作業場所/能力/シフト/仕入先マスタを編集可か）。
   - 根拠：`docs/00` §想定ユーザー（システム管理者: 商品・原料・資材・作業場所・ユーザー・権限の管理）と各管理者の責務が分かれている。具体的ロール定義は docs に明示なし。
2. **生産予定の「確定」承認者**（パイプライン A ステップ1）。
   - 根拠：`docs/17` §9 で「`確定する` を押す」と機能はあるが、誰が押すかは明示なし。
3. **日報の承認者**（パイプライン B ステップ2）と**不在時の代理承認ルート**。
   - 根拠：`docs/18` §17 Phase 5「実績承認者」を着手前確定対象として明示。`docs/文字起こし要約.md` §N は「管理者」とだけ表記。
4. **日報入力者の範囲**（パート/現場担当者の入力可・代理入力可否）。
   - 根拠：`docs/18` §17 Phase 5「日報入力者の範囲」を着手前確定対象として明示。
5. **発注確定の承認者**（パイプライン A ステップ5、購買発注担当者の発注確定が誰の承認を要するか）。
   - 根拠：`docs/00` §想定ユーザーで購買発注担当者の役割は明示されるが、承認フロー有無は docs に明示なし。
6. **自動候補の採用（本予定化）承認者**（パイプライン D ステップ5・C ステップ5）。
   - 根拠：`docs/18` §13-D「人が採用するまで本予定化しない」とあるが「人」の役職は不明。
7. **能力値 lock 操作者**（パイプライン B ステップ6 で `production_capacities.locked=true` を切り替えられる人）。
   - 根拠：`docs/文字起こし要約.md` §P「自動更新した能力値を人が確認・固定できる」とあるが、誰が固定するかは明示なし。
8. **土曜・祝日稼働ルール**（誰の判断で稼働日にするか／シフト作成ルール）。
   - 根拠：`docs/18` §17 Phase 5、`docs/文字起こし要約.md` §8-10 で確認要事項として明示。
9. **タブレット日報の入力デバイス前提**（Wi-Fi 到達範囲、配備端末数、共有運用 or 個人運用）。
   - 根拠：`docs/18` §17 Phase 5、`docs/文字起こし要約.md` §5 で前提として明示。
10. **15日単位の希望シフト収集ルール**（収集者・取り纏め者）。
    - 根拠：`docs/15` §17 で未確認事項として明示。
11. **作業場所マスタの追加・改廃の権限者**（CLAUDE.md ルールで「部屋名や外注先名は固定値にせず、マスターで追加・変更できるようにする」とされる以上、追加権限者を決める必要がある）。
    - 根拠：CLAUDE.md ＋ `docs/15` §1。

→ **Phase 1 着手前に確定が必要な人系要件は計 11 件**（うち 4・8・9 は Phase 5 の確定事項だが、マスタ設計に必要なため Phase 1 開始前に揃えるのが望ましい。残り 7 件は Phase 1 直接関連）。

このサブタスクで決められない、後続サブタスクや人間判断に回すべき事項：
