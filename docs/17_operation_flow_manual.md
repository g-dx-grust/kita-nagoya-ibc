# 17. 操作の流れマニュアル

このマニュアルは、現在実装済みの画面で「実際にどう動くか」を確認し、業務上正しいかどうかを判断するための確認手順です。

対象は `app/` の Phase 0 + Phase 1 MVP 画面です。Phase 2 以降の一部機能はデータモデル/APIのみ実装されており、画面操作だけでは完結しない箇所があります。

## 0. 起動と前提

作業ディレクトリ:

```bash
cd app
```

初回またはDBを作り直す場合:

```bash
npm install
npx prisma generate
npx prisma db push
npm run db:seed
npm run dev
```

ブラウザで開く:

```text
http://localhost:3000
```

サンプルデータの前提:

- 商品: `P001 サンプル商品A`
- 作業場所: `一般部屋`
- 生産能力: `100 袋/人時`
- BOM: 原料X `0.05 kg/袋`, 標準袋 `1 枚/袋`
- 現在庫: 原料X `20 kg`, 標準袋 `5000 枚`
- 請求単価: 商品A `12 円/袋`

## 1. まず見る場所

トップページ `/` を開きます。

確認すること:

- 上部ナビに `ダッシュボード`, `生産予定`, `在庫`, `商品`, `原料`, `資材`, `作業場所`, `従業員`, `請求出力` が表示される。
- `直近の生産予定` に予定があれば、日付・商品・作業場所・数量・開始・終了・状態が見える。
- `開く` から生産予定詳細へ移動できる。

判断してほしいこと:

- 現場で最初に見たい情報として足りているか。
- 予定の状態表記が `仮`, `確定`, `完了`, `取消` で分かりやすいか。

## 2. マスター確認

### 2.1 作業場所

画面: `/masters/work-areas`

確認すること:

- `一般部屋`, `機械部屋`, `外注先A` が表示される。
- 部屋名・外注先名は固定ではなく、マスターで追加できる。
- `＋ 新規 (work-area)` から名称と表示順を登録できる。
- `自動予定の役割` で `受注生産を優先`, `在庫生産を優先`, `共用`, `自動予定から除外` を設定できる。

判断してほしいこと:

- 作業場所の呼び方、種別、標準開始/終了の持ち方が実務に合うか。
- 外注先を作業場所として扱う方針でよいか。
- 受注生産向けの部屋、在庫生産向けの部屋、共用部屋の切り分けが現場の運用に合うか。

### 2.2 商品

画面: `/masters/products`

確認すること:

- 商品一覧に `商品番号`, `正式名称`, `区分`, `標準作業場所`, `BOM`, `生産能力`, `請求`, `状態` が表示される。
- `P001 サンプル商品A` は BOM が2行、生産能力が1行ある。
- `編集` を押すと商品詳細へ移動する。

商品詳細で確認すること:

- `基本情報`: 正式名称、表示名、区分、単位、標準作業場所、請求対象、有効、別名を編集できる。
- `BOM (原料・資材)`: 原料/資材、商品1単位あたり使用量、単位、ロス率を編集できる。
- `生産能力 (1時間1人あたり生産量)`: 作業場所別の `生産量 / 人時`, 標準人数を保存できる。

判断してほしいこと:

- 商品1単位あたりのBOM入力で実務上問題ないか。
- ロス率の入力単位が分かりやすいか。
- 生産能力を「商品 x 作業場所」で持つ形でよいか。

### 2.3 原料・資材・従業員

画面:

- `/masters/materials`
- `/masters/packaging`
- `/masters/employees`

確認すること:

- 原料は `原料番号`, `正式名称`, `単位`, `標準単価`, `リードタイム(日)` を登録できる。
- 資材も同様に資材番号、名称、単位、標準単価を登録できる。
- 従業員は名前などの基本情報を登録できる。
- 従業員ごとに `本人入力URL` を発行/コピーできる。
- 本人入力URLを開くと、スタッフ本人が月ごとの出勤可能日と基本時間を登録できる。
- 原料/商品はCSV取り込み欄からテンプレートをダウンロードできる。

判断してほしいこと:

- マスター項目が多すぎる/少なすぎる箇所。
- 実際に使うコード体系や名称ルールに合っているか。
- スマホに慣れていないスタッフでも、日付ボタンを押して登録する流れで迷わないか。

## 3. 生産予定を登録する

画面: `/production-plans`

操作:

1. `＋ 新規予定` を押す。
2. `生産予定を新規登録` 画面で次を入力する。

入力例:

| 項目 | 値 |
| --- | --- |
| 生産日 | 任意の日付 |
| 商品 | `P001 · サンプル商品A` |
| 区分 | `在庫生産` |
| 作業場所 | `一般部屋` |
| 数量 | `1000` |
| 単位 | `袋` |
| 人数 | `5` |
| 開始時刻 | `09:00` |
| 終了希望 | `17:00` |
| 基準終了 | `17:00` |
| 仮/確定 | `仮` |

確認すること:

- `計算プレビュー` に `生産能力: 100 袋/人時` が表示される。
- `休憩時間帯: 12:00-13:00 / 15:00-15:15` が表示される。
- `① 数量固定 → 終了時刻` では、終了予定が `11:00` になる。
- `登録する` を押すと、生産予定詳細画面へ移動する。

判断してほしいこと:

- 入力順が現場の考え方に合うか。
- `仮/確定` を登録時に選べる仕様でよいか。
- 終了希望と基準終了の両方が必要か、片方でよいか。

## 4. 計算モードを確認する

画面: `/production-plans/new`

### 4.1 数量固定 → 終了時刻

入力:

- 数量 `1000`
- 人数 `5`
- 開始時刻 `09:00`
- 基準終了 `17:00`

期待結果:

- 所要稼働時間 `120分`
- 休憩時間帯 `0分`
- 所要時間 `120分`
- 終了予定 `11:00`
- 残業見込み `0分`

### 4.2 時間枠固定 → 最大数量

操作:

1. `計算プレビュー` のモードを `② 時間枠固定 → 最大数量` に変える。
2. 開始時刻 `09:00`, 終了希望 `17:00`, 人数 `5` にする。

期待結果:

- 稼働時間 `6.75`
- 最大生産数量 `3375 袋`

### 4.3 数量+時間枠 → 必要人数

操作:

1. モードを `③ 数量+時間枠 → 必要人数` に変える。
2. 数量、開始時刻、終了希望を変えて確認する。

確認すること:

- 必要人数が表示される。
- 人数ごとの終了時刻と残業分が表で表示される。

判断してほしいこと:

- 3つの計算モードの名前が分かりやすいか。
- 実際はどのモードを一番使うか。
- 追加で必要な警告があるか。

画面: `/production-plans/new`

入力例:

| 項目 | 値 |
| --- | --- |
| 商品 | `P001 · サンプル商品A` |
| 作業場所 | `一般部屋` |
| 数量 | `4500` |
| 人数 | `5` |
| 開始時刻 | `09:00` |
| 基準終了 | `17:00` |

期待結果:

- 終了予定が `19:15` になる。
- 残業見込みが `135分` になる。
- `17時(基準終了時刻)を超過します。残業/翌日繰越/外注を検討してください。` の注意が出る。

判断してほしいこと:

- 17時固定でよいか、作業場所ごとの標準終了時刻を基準にすべきか。
- 「翌日繰越」「外注」などの判断候補をどこまで自動表示したいか。

## 6. 原料・資材不足を確認する

画面: `/production-plans/new`

操作:

1. 商品 `P001 · サンプル商品A`、数量 `1000`、作業場所 `一般部屋` で予定を登録する。
2. 登録後の生産予定詳細画面で `原料・資材の予定使用量` を見る。

期待結果:

- 原料Xの予定使用量が `50 kg` になる。
- 原料Xの現在庫が `20` になる。
- 不足が `30 kg` になる。
- 状態が `不足` になる。
- 標準袋は予定使用量 `1000 枚`、現在庫 `5000`、状態 `OK` になる。
- 下部に `原料/資材が不足しています。発注候補: 原料X 30kg` のような警告が出る。

判断してほしいこと:

- 不足量の見せ方が現場で判断しやすいか。
- `現在庫`, `確定入荷`, `未確定入荷` の並びでよいか。
- 不足時に次アクションとして何を表示したいか。

## 7. 生産予定一覧で確認する

画面: `/production-plans`

確認すること:

- 登録した予定が一覧に表示される。
- `開始日`, `終了日`, `状態`, `作業場所` で絞り込みできる。
- アラート欄に `17時超`, `不足`, `未確定依存` が表示される。
- `開く` から詳細画面へ移動できる。

判断してほしいこと:

- 一覧に表示する列が十分か。
- 日別/部屋別で見たい場合、現行の一覧で足りるか、カレンダー・月間表が必要か。

## 8. シフトに合わせて生産スケジュールを自動作成する

画面:

- `/shifts`
- `/production-plans/auto`

操作:

1. `/shifts` で対象日の出勤者、開始時刻、終了時刻、休憩、休みを登録する。
2. `/production-plans/auto` を開く。
3. 対象日、計算モード、開始時刻、終了希望、基準終了、休憩を指定する。
4. `今日作る商品` に商品と数量を追加する。
5. `シフトに合わせて自動作成` を押す。

自動作成で行うこと:

- 商品マスターの区分と作業場所マスターの `自動予定の役割` を見て、受注生産を先に、在庫生産を後工程に配置する。
- 受注生産は `受注生産を優先` の作業場所、在庫生産は `在庫生産を優先` の作業場所を優先する。該当する役割がなければ `共用` など登録済み候補へフォールバックする。
- 対象日の出勤シフトに入っているスタッフだけを使う。
- 休み、またはシフト未登録のスタッフは配置しない。
- 同じ作業場所では前の作業が終わってから次の作業を入れる。
- スタッフが別作業へ移る場合は、印刷HTMLで移動時刻と移動先を出す。

判断してほしいこと:

- 受注生産を優先し、最後に在庫生産へ合流する順番でよいか。
- 商品ごとの優先度、納期、得意な作業場所の追加設定が必要か。
- 休憩の扱いを作業ごとに見るか、勤務シフト全体で見るか。

## 9. 生産予定を詳細画面で更新・確定する

画面: 生産予定詳細 `/production-plans/{id}`

操作:

1. `登録内容` の数量、人数、開始時刻などを変更する。
2. `更新する` を押す。
3. 必要量、終了予定、原価見積が再計算されることを確認する。
4. `再計算` を押す。
5. `確定する` を押す。
6. `取消` を押す場合は状態が取消になることを確認する。
7. `削除` は確認ダイアログ後に予定を削除する。

注意:

- `確定する` は予定ステータスを確定にする操作です。
- 予定確定だけでは実在庫は減りません。
- 実在庫の消費は日報確定時に `actual_consume` として台帳に記録される設計です。

判断してほしいこと:

- 予定確定と実績確定の分離が業務に合うか。
- 詳細画面で編集と確定操作が同じ場所にあるのが分かりやすいか。

## 10. スタッフ配置を登録する

画面: 生産予定詳細 `/production-plans/{id}`

操作:

1. `スタッフ配置` の `＋ スタッフを追加` を押す。
2. スタッフ、開始、終了を入力する。
3. `スタッフ配置を保存` を押す。

確認すること:

- 同じ予定に同じスタッフを重複登録しようとすると保存できない。
- 同じ日の別予定と時間が重なるスタッフ配置は保存できない。
- 保存したスタッフが印刷HTMLに反映される。

判断してほしいこと:

- スタッフを予定ごとに登録する運用でよいか。
- 時間の重複を完全禁止でよいか、警告承認にすべきか。
- 合流・移動の表現として追加したい項目があるか。

## 11. 現場印刷HTMLを確認する

画面: `/prints`

操作:

1. `対象日` を選ぶ。
2. `表示` を押す。
3. `生産スケジュール印刷` または `スタッフ配置印刷` を開く。
4. 印刷ページで印刷ボタンを押す、またはブラウザの印刷機能を使う。

生産スケジュール印刷で確認すること:

- 対象日の生産予定が作業場所別に並ぶ。
- 時間、商品、区分、数量、予定人数/配置人数、スタッフ、注意、メモが出る。
- 17時超過、原料/資材不足、未確定入荷依存が注意欄に出る。

スタッフ配置印刷で確認すること:

- `作業場所別配置` で場所ごとの予定と配置スタッフが見える。
- `スタッフ別配置` でスタッフごとの移動時刻、配置時間、作業場所、商品が見える。
- 休み、またはシフト未登録のスタッフは表示されない。
- 出勤しているが未配置のスタッフは `未配置` と表示される。
- 印刷時は上部ナビや操作ボタンが消え、HTML本文だけが印刷される。

判断してほしいこと:

- 紙に出す項目、並び順、余白、横向き/縦向きが現場で使えるか。
- 生産スケジュールとスタッフ配置を1枚にまとめるか、別紙でよいか。
- 手書き用の空欄、チェック欄、責任者サイン欄が必要か。

## 12. 在庫画面を確認する

画面: `/inventory`

操作:

1. `基準日` を変更する。
2. `更新` を押す。

確認すること:

- 原料と資材が別表で表示される。
- `現在庫`, `確定入荷`, `未確定入荷` が表示される。
- サンプルでは原料Xが `20 kg`, 標準袋が `5000 枚` になっている。

判断してほしいこと:

- 在庫画面に予定使用量や実使用量も必要か。
- 原料と資材を同じ画面で見るか、分けるか。
- 発注候補作成ボタンをどこに置くべきか。

## 13. 請求CSV出力を確認する

画面: `/invoices`

操作:

1. `開始日` と `終了日` を指定する。
2. `請求対象のみ` を選ぶ。
3. `CSVを出力` を押す。

現在の画面上の注意:

- 請求CSVは、確定済みの日報をもとに出力します。
- 現在は日報入力画面が未実装のため、通常の画面操作だけでは請求対象行が作られません。
- 出力対象がない場合は `0件出力 / 合計 ¥0` になります。

判断してほしいこと:

- 出力条件は日報確定後でよいか。
- CSVの列は `生産日`, `商品コード`, `商品名`, `実数量`, `単位`, `単価`, `金額`, `請求先` で足りるか。
- FXクラウド等に合わせて列名や順番の修正が必要か。

## 14. 日報・実績反映の現在地

現在の実装状態:

- 日報下書き作成 API はあります。
- 日報確定 API はあります。
- 日報入力用の画面はまだありません。

APIでできること:

- 生産予定から日報下書きを作る。
- 実数量、実時間、実人数、実原料/資材使用量を登録する。
- 日報を確定すると、在庫台帳に実消費が記録され、生産予定は `完了` になる。

業務判断ポイント:

- 日報入力画面に必要な項目。
- 予定使用量を初期値として出し、実使用量だけ修正する形でよいか。
- 誰が、いつ、どの状態で日報を確定するか。

## 16. 依頼時の書き方例

修正依頼は次の形で書くと、そのまま実装に落とし込みやすいです。

```text
画面: 生産予定登録
現状: 終了希望と基準終了が別々にある
修正したい内容: 現場では基準終了は作業場所マスターから自動で入り、画面では終了希望だけ入力したい
理由: 入力項目を減らしたい
期待結果: 一般部屋なら基準終了17:00、機械部屋なら17:30が自動セットされる
```

```text
画面: 原料・資材の予定使用量
現状: 不足量は表示されるが、発注単位や仕入先が見えない
修正したい内容: 不足行に仕入先、リードタイム、発注候補数量を表示したい
理由: そのまま発注判断に使いたい
期待結果: 原料X 不足30kg / 仕入先A / LT3日 / 発注候補30kg のように表示される
```
