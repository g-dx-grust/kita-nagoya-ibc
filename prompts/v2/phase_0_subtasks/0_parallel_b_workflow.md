# Phase 0-B: 業務フロー整理（0-1〜0-3 と並列）

## 使用ツール

Claude Code

## 目的

`docs/17_operation_flow_manual.md` の業務フローと、`docs/18_implementation_phase_plan.md` §13（実行時パイプライン A〜D）の差分を可視化し、運用とシステムの噛み合わせポイントを明らかにする。**現場運用に乗らない実装を防ぐ**ための基礎資料。

## 前提

- 推測で運用を決めない。**ドキュメントに書かれていることだけ**から差分を出す。
- 出力先：`docs/phase_0_outputs/0_b_workflow_diff.md`

## 読むファイル

- `docs/17_operation_flow_manual.md`
- `docs/00_project_overview.md`
- `docs/01_current_workflow_and_excel_assets.md`
- `docs/文字起こし要約.md`（§N 日報、§O 実績反映、§A 受注・出荷取込 を中心に）
- `docs/18_implementation_phase_plan.md` §13（パイプライン A〜D）
- `docs/15_open_questions.md`

## やってほしいこと

1. **アクター × フェーズ**の責務マトリクスを作る：
   - アクター：製造管理者／現場担当者／購買発注担当／管理経理／システム管理者
   - フェーズ：Phase 1〜9
   - セルには「誰が何をする」を1〜2行で。
2. パイプライン A〜D それぞれについて、**現場で誰がトリガーするか／システムが受け取るか／承認は誰か**を分解。
3. 既存業務との **段差**を抽出（例：紙の日報→タブレット入力で発生する変化点、承認フロー導入による工数増、未確定発注の取り扱い変更）。
4. **段差を許容するための前提条件**を列挙：Wi-Fi、タブレット端末数、承認者の常駐／不在対応、現場入力者の権限範囲。
5. `docs/15_open_questions.md` と `docs/18` §17 未確認事項の**重複と差分**を表にする。
6. 業務フロー視点で、**Phase 1 着手前に確定が必要な人系の要件**を箇条書き化（権限ロール、承認ルート、土曜稼働ルールなど）。

## 完了条件

- ファイルが書き出されている。
- アクター × フェーズマトリクスがすべてのセルに記述あり（不明は「未確定」と明記）。
- パイプライン A〜D すべてに主体が定義されている。

## 絶対にやらないこと

- アクター名・部屋名・外注先名を推測で書く（**ドキュメント記載のみ**）。
- システム実装の提案。
- `docs/17_operation_flow_manual.md` の編集。
