# Phase 0-0: 既存リポジトリ・ドキュメント棚卸し（起点）

## 使用ツール

Claude Code

## 目的

Phase 0 の起点として、リポジトリ全体の構成と、docs/ 配下のドキュメント体系を棚卸しする。後続サブタスク（0-1〜0-C）が共通で参照する **目次マップ** を作る。

## 前提

- 既存 `app/` のコードは**1行も変更しない**。
- 既存ドキュメントの内容は**書き換えない**。読むだけ。
- 出力先：`docs/phase_0_outputs/0_0_orientation.md`

## このフェーズで読むファイル

- `CLAUDE.md`（プロジェクト方針）
- `AGENTS.md`
- `README.md`
- `docs/00_project_overview.md`
- `docs/18_implementation_phase_plan.md`（**新ターゲット。ここが正**）
- `docs/02_phase_0_foundation_and_master_data.md` 〜 `docs/08_phase_6_product_stock_auto_planning.md`（旧版だが参考）
- `docs/文字起こし要約.md`
- `docs/gpt新規実装.md`
- `app/` 配下のディレクトリ構造（ls まで。中身は 0-1, 0-2 で読む）

## やってほしいこと

1. リポジトリ全体のディレクトリツリーを 2 階層まで出す。
2. `docs/` 配下のファイル一覧を表にする（ファイル名、1行サマリ、新ターゲット docs/18 との関係：[正] / [参考] / [素材]）。
3. `app/` 配下の Next.js 構造を 2 階層まで出す（`node_modules` は除外）。
4. CLAUDE.md の方針と docs/18 のフェーズマップを突き合わせ、**今後の実装で守るべき不変ルール**を箇条書きで抽出する（例：「自動生成結果はまず候補保存」「planned/actual 分離」「外注/AX の請求対象フラグ」）。
5. 旧版 docs/02〜08 と新版 docs/18 の対応表を作る（旧 Phase X = 新 Phase Y、または「旧版は破棄」と明記）。
6. **判断保留事項**を列挙：このサブタスクで決まらない・他のサブタスクや人間判断に回すべき事項。

## 完了条件

- `docs/phase_0_outputs/0_0_orientation.md` が存在する。
- 既存ファイルは何も変更されていない（`git status` で `docs/phase_0_outputs/` 以下しか差分が出ない、もしくは git 管理外なら新規ファイルのみ）。
- 不変ルールが 8 個以上抽出されている。

## 絶対にやらないこと

- `app/` 配下の編集。
- `prisma/schema.prisma` の編集。
- 既存 `docs/00_*.md`〜`docs/17_*.md` の編集。
- 「設計を提案する」「マイグレーションを書く」など、調査を超える行為。
- ファイル名や URL の推測。実在を確認してから書く。
