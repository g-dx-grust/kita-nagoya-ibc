# Phase 0-C: テストカバレッジ差分洗い出し（0-1〜0-3 と並列）

## 使用ツール

Claude Code

## 目的

既存の Vitest テストと `docs/14_acceptance_tests.md` を突き合わせ、Phase 1 以降で追加すべきユニットテスト・統合テストの **過不足リスト** を作る。CLAUDE.md「計算式はユニットテスト化する」の網羅性を担保するための地図。

## 前提

- テストの新規作成・実行は**しない**。リストアップのみ。
- 出力先：`docs/phase_0_outputs/0_c_test_coverage_diff.md`

## 読むファイル

- `app/src/lib/` 配下の `*.test.ts`（テスト名から責務を読み取る）
- `app/package.json`（test スクリプトと vitest 設定の確認）
- `app/vitest.config.ts`
- `docs/14_acceptance_tests.md`
- `docs/18_implementation_phase_plan.md` の各フェーズの完了条件と §15 監査表
- `CLAUDE.md`（受け入れ基準）

## やってほしいこと

1. 既存テストファイル一覧を作る（ファイル、テストケース概要、カバーしている関数）。
2. docs/14 の受け入れテストケースに対し、既存テストでカバーされているか／部分／未カバーを判定。
3. docs/18 各フェーズの完了条件のうち、**ユニットテストで検証すべき計算式**を抽出：
   - Phase 3: 所要時間計算、時間枠あふれ判定
   - Phase 4: BOM 展開、リードタイム逆算、緊急度判定
   - Phase 5: 予定 vs 実績差分、能力値中央値
   - Phase 6: 手間賃、原価集計
   - Phase 8: 前年比率予測、シナリオスコアリング
   - Phase 9: 異常検知の閾値判定
4. **統合テスト（E2E）が必要な箇所**を別表で抽出：日報承認 → 在庫反映、発注候補承認 → 在庫増、CSV 取込 → staging → 本反映 など。
5. **テストデータ（Seed）に必要な雛形**を列挙：商品、原料、BOM、シフト、能力、出荷予定、サンプル日報 など。`prisma/seed.ts` の現状もメモ。
6. テスト基盤の現状（vitest 設定、モック方針、DB の扱い）を1段落で記録。

## 完了条件

- ファイルが書き出されている。
- 既存 `*.test.ts` がすべて表に出ている。
- docs/14 の各ケースに対応関係が付いている。
- Phase 3〜9 の主要計算ロジックすべてに追加テスト要件が割り当てられている。

## 絶対にやらないこと

- テストの新規作成。
- 既存テストの編集。
- `vitest` 実行。
- `prisma/seed.ts` の編集。
